# ASCENDRA Enterprise v1.0 — Security & Compliance Architecture

ASCENDRA incorporates defense-in-depth security mechanisms designed to protect student data, biometric descriptors, and execution integrity.

---

## 1. Biometric Facial Descriptor Security
- Facial embeddings generated by MediaPipe are encrypted prior to database persistence using **AES-256-GCM**.
- Key rotation and initialization vectors (IV) are unique per record.

## 2. Sandboxed Code Execution
- User code submitted in CodeLab executes inside isolated Node.js VM contexts.
- Regex input sanitization blocks restricted system calls (`require('fs')`, `child_process`, `process.exit`, `eval`).
- Hard execution timeouts (2000ms limit) prevent infinite loop memory starvation.

## 3. Role-Based Access Control (RBAC)
- All administrative and faculty endpoints are guarded by strict role middleware (`requireAdmin`, `requireFaculty`).
- Administrative actions generate immutable records in `AuditLog.model.js`.

## 4. Operational Safety Rules
- AI content generated in Faculty Portal remains `DRAFT_REQUIRES_REVIEW` until human faculty confirmation.
- AI grading recommendations require explicit human faculty confirmation before publishing scores.
